# Swibo 統合（オプション）

状態: オプション統合 — 外部スーパーバイザーテンプレート

Swibo は、ローカル MCP バックエンドサービスとゲートウェイターゲットのライフサイクルを管理するためにリファレンスデプロイで使用される外部プロセススーパーバイザです。コアゲートウェイはバックエンドプロセスの起動・停止・監視を行いません。その責務はこのリポジトリの外で、Swibo（または同等のスーパーバイザ、あるいは手動起動）が担います。

## コア独立性

- `src/` は Swibo のコードをインポートせず、`Cargo.toml` に Swibo 依存もありません。Swibo がインストールされていなくても、ゲートウェイはコンパイル・テスト・サービス提供ができます。
- `scripts/` のラッパーはゲートウェイの CLI と HTTP エンドポイントのみを呼び出し、Swibo ターゲットについて何も知りません。
- Swibo は純粋に外部プロセスマネージャとして Lomway と相互作用します。つまり `lomway serve --config <path>` を起動し、`GET /healthz` を監視します。

## リファレンスのライフサイクル順序

```text
Start: バックエンドサービス -> ゲートウェイ -> Secure MCP Tunnel（オプション統合）
Stop:  Secure MCP Tunnel -> ゲートウェイ
```

集約ゲートウェイターゲットの停止は、いかなるバックエンドも停止しません。

## テンプレート

以下のプレースホルダーパラメータをローカルの Swibo 環境に合わせて調整してください。このテンプレートにはマシン固有の絶対パスを意図的に含めていません。すべての値はチェックアウト相対または環境変数から取得します。

| パラメータ | プレースホルダ値 | 意味 |
| --- | --- | --- |
| ターゲット名 | `<gateway-target>` | ゲートウェイを包む Swibo ターゲット。 |
| コマンド | `lomway serve --config <config-path>` | 現行の Lomway 起動コマンド。 |
| 作業ディレクトリ | `<repo-root>` | このリポジトリのチェックアウトルート。 |
| ヘルスプローブ | `http://127.0.0.1:<port>/healthz` | 存活エンドポイント（既定ポート `17777`）。 |
| 順序付きコンポーネント | `<gateway-target>`, `<tunnel-target>` | 集約ターゲットの起動/停止順序。 |

各 `<placeholder>` はローカルのスーパーバイザ設定内でのみローカル値に置き換えてください。マシン固有の値をコミットしないでください。
